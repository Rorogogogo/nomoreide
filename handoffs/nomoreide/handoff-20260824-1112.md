## Key decisions & constraints

**Never derive behaviour from reading the TypeScript.** Launch the reference and
diff it. TS is read only for plumbing (field names, where a message lives).

**Standing user rules — do not relitigate:**
- *"no pr until the refactory is 100% finished and tested bro"* — no
  `gh pr create` on this branch at any point.
- *"now I think it's ok to push just dont pr is ok"* — pushing is authorized.
- Never `git stash` in this tree (parallel writers).

**Push recipe** (token must never reach `argv`; the empty `credential.helper=`
reset must come first so the keychain cannot push as the wrong account):

```
NMI_TOKEN="$(gh auth token)" git \
  -c credential.helper= \
  -c credential.helper='!f() { echo username=x-access-token; echo "password=$NMI_TOKEN"; }; f' \
  push origin rust-refactoring 2>&1 | sed -E 's/gh[pous]_[A-Za-z0-9]+/[redacted]/g'
```

**Gate-writing lessons worth carrying into the terminal gate:**
- `assert.deepStrictEqual` treats objects as unordered. The agent-env, profiles
  and registry gates add an explicit `JSON.stringify` comparison so key order
  and call order are held too. Do the same.
- When a tool's answer cannot distinguish two behaviours, compare the
  *side channel* instead: the registry gate compares the recorded request log
  because a publish reports the same four fields whether it uploaded or not.
  A terminal gate will likely need the same trick against spawn arguments.
- End every seeded-regression sweep with `restore()` **and** `cargo build`.
  See memory `rebuild-after-a-seeded-sweep`.
- Bash tool timeout caps at 600000 ms; background anything longer.

## Open questions / blockers

**How does a terminal session come to exist?** No MCP tool creates one — the
dashboard and the agent-run path do. That is the same "state no tool creates"
problem the deploy connections had, and it is unsolved for terminals. Probe the
reference first and establish:

1. What records a session, and where (file? daemon memory only?).
2. Whether `open_terminal` itself registers one, or only attaches.
3. What `reclaim_terminal` needs in order to have anything to reclaim.

Only then decide whether the gate can plant sessions directly or has to drive
the daemon's HTTP routes to create them.

**Deliberately deferred, still outstanding:**
- Bundled-plugin apply — needs its own probing; TS `plugin-apply.ts` is 507
  lines and the current fixture cannot produce a bundled plugin.
- Phase 5 exit gate also asks for agent process orchestration and the approval
  broker in shared core services.

**Known accepted divergence:** `profiles_import` with `as: ".."` can write above
its root. Mirrored rather than fixed, because fixing Rust alone breaks parity.
Needs a joint TS+Rust change later — memory
`profiles-import-can-write-above-its-root`.
