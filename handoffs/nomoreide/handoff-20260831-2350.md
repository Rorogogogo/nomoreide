## Failed approaches

- **`cargo package`/`--dry-run` for the five dependent crates is impossible**
  before their siblings are on the registry — it fails at *"failed to prepare
  local package for uploading"*, even with `--no-verify`. So the plan to build
  every tarball and cross-build them in a temp workspace does not work. This is
  cargo's ordering constraint, not something left unchecked.
- **`perl -0pi -e` mangles JS/TS template literals** — `${name}` interpolates as
  a perl variable and silently empties. It bit me four times in
  `sync-version.mjs`, `publish-crates.mjs` and `vendor-crate-assets.mjs`.
  Prefer writing whole files with a heredoc, or escape as `\$\{name\}`.
- `node -e "import('./scripts/publish-crates.mjs')"` as a syntax check **executes
  the script**. Use `node --check`. (It was killed by SIGPIPE before publishing;
  verified nothing reached crates.io.)

## Key decisions & constraints

1. **Recordings are a decaying asset.** Their original job — proving the port —
   is finished. What is left is regression value that cannot be regenerated,
   because re-recording needs the deleted TypeScript reference. Agreed policy:
   keep them for now, and **as a gate blocks a deliberate change, convert what it
   protected into a native Rust test and delete the gate.** Do not add new gates.

2. **The user chose: add the harnesses and retire the 6 blocked gates.**
   Adding a 4th `Agent` changes two recorded outputs — the `/api/agent-env`
   array (which lists *every known* agent, installed or not) and the MCP schema
   error `Expected 'claude' | 'codex' | 'antigravity'`. The affected gates are
   **agent-env, agent-profiles, cli, mcp-agent-env, mcp-profiles, mcp**.
   No recording can ever show a 4th agent, because the reference never knew
   about Cursor. Replace their coverage with Rust tests asserting *correct*
   behaviour, then delete those `scripts/check-*-parity.ts` and their
   `test/expectations/*.json`.

3. **Cursor and Windsurf only; VS Code deliberately excluded.** VS Code's user
   MCP config lives inside a per-profile directory with no stable home-relative
   path — the docs point at an *"MCP: Open User Configuration"* command rather
   than a filename. Guessing it would mean writing to the wrong file.
   Workspace-scoped `.vscode/mcp.json` is well-defined if the user prefers that.

4. **Archive layout left alone.** Embedding makes `share/nomoreide/web/client`
   unnecessary, but `install.sh` and `check-install.sh` read `build-info.txt`
   from that prefix for version detection and uninstall. Dropping it is a
   separate change with its own test sweep.

5. `dist/`-first over vendored-first in every `build.rs`, so a checkout can
   never compile a stale vendored copy. A published crate has no `dist/` above
   it, so it gets the fallback.

## Open questions / blockers

- **crates.io publishing is irreversible** (yank hides, never frees a version).
  `scripts/publish-crates.mjs` is written and safe to re-run — it skips what is
  already published — but **ask the user before running it without `--dry-run`.**
  It was not run in this session.
- Publish order is forced: `nomoreide-core` → `nomoreide-daemon-client` →
  `nomoreide-actions` → `nomoreide-daemon` → `nomoreide-mcp` → `nomoreide-cli`.
  A failure partway is recoverable (fix, re-run, it skips) *unless* the fix must
  change an already-published crate — then that one needs a patch bump.
- A re-sweep is worth doing once the embed work and the gates branch are on the
  same commit — they have only been swept separately.
