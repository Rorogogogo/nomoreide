## Review blockers to fix

1. **Windows starts are currently nonfunctional.** The daemon always enables `RuntimeRegistry`, but non-Unix `inspect_process_identity` returns `None`, so registered starts time out and kill the child. Windows reconciliation also rejects every persisted record, so a crash leaves the next daemon unable to publish. See `crates/nomoreide-core/src/port_utils.rs` and `process_manager.rs` around `wait_for_process_identity` / `reconcile_runtime_record`.
2. **Managed services can become impossible to stop after config drift.** `DaemonRuntime::stop_service` reloads and requires a current local registration before stopping. Permit stopping a name already owned by `ProcessManager` even if config was removed, changed, or is temporarily unreadable; retain registered-local checks for unmanaged names. Add integration regressions.
3. **Registry cleanup retry can falsely succeed.** `stop_service_locked` returns immediately for `Stopped` even when `cleanup_confirmed == false`. Retry the registry cleanup and mark confirmed only on success. Add a fail-then-retry registry regression and verify daemon shutdown remains refused until durability cleanup succeeds.
4. **Unix launch has an unjournaled crash window.** The child executes before its exact identity record is durable. A daemon crash during identity capture/write leaves a live unrecorded process group. Design a crash-safe pending-launch/handshake before editing; add a black-box crash-at-launch-stage test.

Security review found no separate findings at >=80% confidence.

## Key decisions and constraints

- Keep the concrete daemon-local coordinator; do not rewrite core into a global actor.
- Start remains registered-local-only and uses config definitions, never request-supplied commands/argv/env.
- Stop must remain a safe cleanup/remediation capability after config drift or daemon cleanup failure.
- Registry stays private, versioned, and separate from TypeScript `~/.nomoreide/runtime.json`: `<state-dir>/native/runtime-v1.json`.
- Recovery must complete before daemon state/credential publication.
- Cleanup failure retains listener, health, credential, and ownership; new starts remain blocked, remedial stops and later shutdown retries remain possible.
- Preserve owner pinning/revalidation before bearer transmission, loopback-only binding, request timeouts, argv execution, exact process identity checks, and MCP stdout purity.
- Tauri still owns its existing runtime; do not claim full production convergence or Phase 2 completion.
