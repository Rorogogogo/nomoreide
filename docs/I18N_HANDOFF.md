# i18n (Chinese) — Handoff / Continuation Plan

Goal: translate the **entire web client** (`apps/dashboard/src`) to Simplified Chinese, switchable from Settings → Language. English + 简体中文.

## How the i18n system works (already built)

Dependency-free, homegrown. Lives in `apps/dashboard/src/lib/i18n/`:

- **`index.tsx`** — `I18nProvider`, `useT()`, `useLanguage()`, `interpolate()`.
  - `const t = useT();` then `t("some.key")` or `t("some.key", { name, count })`.
  - Interpolation: `{name}` placeholders in the catalog string, filled from the params object.
  - Resolution order: `zh[key] ?? en[key] ?? key` — so any untranslated key falls back to English automatically.
- **`en.ts`** — source-of-truth catalog (`as const`) + `TranslationKey` type. Every key MUST be added here.
- **`zh.ts`** — `Partial<Record<TranslationKey,string>>` Simplified Chinese overrides.
- **`lib/language.ts`** — `Language` type, `LANGUAGE_OPTIONS`, `getStoredLanguage` (pure helpers only).
- `App` wraps `AppBody` in `<I18nProvider>` (in `app.tsx`) so real app + website embed both get it.

### The mechanical pattern for each file
1. `import { useT } from "@/lib/i18n";`
2. Add `const t = useT();` at the top of **each component/function that renders text** (sub-components need their own `useT()` — hooks can't cross component boundaries).
3. Replace each user-facing string literal with `t("feature.key")`. Covers: JSX text, `title`, `aria-label`, `placeholder`, button labels, toast messages, `alert`/confirm text, `<option>` labels, empty-state text.
4. Add the key to BOTH `en.ts` (English) and `zh.ts` (Chinese).
5. For plain (non-component) helper functions that build strings (e.g. toast helpers), pass `t` in as a param (see `showGroupTransitionToast` in `services-view.tsx`, or `collectEntries` in `running-stripe.tsx`).
6. For arrays of options defined at module scope (labels), store a `labelKey: TranslationKey` and call `t(labelKey)` at render (see `TIME_RANGES` in `service-detail/log-console.tsx`, `TYPE_HINT_KEYS` in `log-source-form.tsx`).

### CONVENTIONS (important — user feedback)
- **Keep these proper nouns in English, do NOT translate:** `Agent`, `Git`, `GitHub`, `PR`, `CI`, `SQL`, `Codex`, `Claude Code`, `NoMoreIDE`, `Issues`, `Actions`, `HTTP`, `SSH`, `Docker`, `Docker Compose`, `RSS`, `CPU`, `MB/GB`, `journald`, and shell/command snippets.
- Namespace keys by feature: `services.*`, `git.*`, `github.*`, `database.*`, `errors.*`, `common.*`. Use `common.*` for shared words (Cancel/Save/Close/Copy/etc. — already defined).
- Don't translate example placeholders that are literal values (e.g. `placeholder="npm run dev"`, `"PROD"`, `"3001"`) — those are illustrative, leave as-is.
- For dense technical paragraphs with many inline `<code>` where Chinese word order differs, translate as ONE `t()` string with the code shown as inline backticks (see `services.form.sshBody`) rather than fighting per-token segments.
- Verify after each feature: `cd apps/dashboard && npx tsc --noEmit 2>&1 | grep "error TS" | grep -vE "snapshots-tauri|tauri-bridge|terminal-tauri"` (those 3 tauri files have PRE-EXISTING errors — ignore them). Then `npm run build` from repo root (must exit 0), and the website build (`npm --prefix apps/website run build`).
