# NoMoreIDE external Send-to-Agent handoff

## Goal / current focus

Make **Send to agent** insert an unsubmitted prompt into a running externally presented Codex/Claude session. It must use the daemon-owned PTY without reclaiming the session, mounting a dock viewport, changing external resize ownership, or restarting the agent.

## State

External-terminal UX is implemented and live-verified:

- external sessions unmount dock xterm/WebSocket/Tauri listeners and show the opaque placeholder plus **Bring back**;
- Ghostty opens one tab with provider-first title such as `🟢 CODEX · <task> · NoMoreIDE`;
- provider tab accents remain separate from the health dot;
- reclaim preserves the same PTY and accepts input;
- hidden viewports no longer resize the PTY, and WebSocket reattach no longer injects fallback `80x24` dimensions.

Verification passed: 116 focused tests, `npm run build`, and `git diff --check`. Final live reclaim returned the same `term_1` at `360x50`. Daemon PID `41125` and the verified task were deliberately left running; ask before restarting the daemon or closing Ghostty windows.

## Why Send to agent currently misses external sessions

- `src/web/client/src/features/agent/terminal/agent-terminal-dock.tsx`
  - `deliveryTargets` excludes `presentation === "terminal"` and `"terminalLaunching"`.
  - `insertDeliveryIntoTask` requires a mounted `TerminalViewportHandle` and calls `handle.paste(prompt)`.
- External presentation intentionally has no viewport handle.
- `src/core/terminal-manager.ts::writeFromDock` correctly rejects input unless presentation is `dock`; do not weaken this ownership gate.

## Recommended next slice

1. Add an explicit manager operation such as `insertAgentPrompt(id, prompt)`:
   - existing running `kind === "agent"` only;
   - allow `dock` and `terminal`, reject `terminalLaunching`;
   - write to the same `TerminalSession`, preserve presentation/size/process, reset idle time;
   - keep `writeFromDock` and `resizeFromDock` unchanged.
2. Add a guarded `POST /api/terminal/sessions/:id/insert-prompt` endpoint and matching HTTP/Tauri `TerminalApi` methods.
   - reuse `x-nomoreide-terminal-control: 1`;
   - validate ID, prompt type/size, and terminal-control characters.
3. Preserve draft-not-submit behavior. Verify bracketed-paste encoding for both Codex and Claude; current xterm `paste()` decides wrapping from terminal mode, while a direct daemon write will need deliberate encoding.
4. Include stable `presentation === "terminal"` tasks in delivery targets, still excluding shells and `terminalLaunching`.
   - dock targets keep using viewport `paste()`;
   - external targets call the explicit API asynchronously;
   - retain the existing multi-target chooser and success/error feedback;
   - never open/reclaim/focus a dock viewport for external delivery.
5. Add manager, HTTP/API, dock, and Tauri/Rust regression coverage. Live-verify a real product action inserts an unsubmitted draft into Ghostty while session ID, presentation, PTY process, and dimensions remain unchanged.

## Constraints

- The daemon always owns the PTY; external presentation owns user input and resize.
- Prompt insertion is a separate trusted product action, not ordinary dock WebSocket input.
- Do not auto-submit unless explicitly requested.
- Preserve guarded relay/authentication and one-time skill behavior.
- The worktree contains extensive unrelated dirty changes. Do not broadly format, reset, restore, or edit generated `dist/` output.
- Important untracked feature files include `src/core/external-terminal.ts`, `test/external-terminal.test.ts`, and `src-tauri/src/core/external_terminal.rs`.
