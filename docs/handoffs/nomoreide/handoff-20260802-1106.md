# Database explorer and MCP handoff

## Goal / current focus

Implement the approved pragmatic database vertical slice across Node/web, MCP, React, and Tauri:

- Add MCP database registration and connection checking.
- Let MCP enumerate and read richer database objects while remaining read-only for database contents.
- Replace the single-connection flat table list with a collapsible DataGrip-style explorer containing every in-scope connection.
- Achieve real HTTP/Tauri contract and safety parity.

## State

- Discovery and architecture are complete; the user explicitly approved implementation.
- No database feature files were edited in this session.
- Multiple connections per project already work when their names are globally unique.
- Existing MCP tools already support masked connection listing, flattened table/view listing, row sampling, and read-only queries.
- Implementation is next. Start with contracts and security tests, then work through the sequence below.

## Approved decisions and constraints

- Keep connection names globally unique. Do not introduce IDs or change config version.
- Explorer hierarchy is lazy: connection -> schema -> category -> object. Categories are Tables, Views, Materialized Views, Functions, Procedures, and Sequences. Tables expose Columns, Indexes, Constraints, and Triggers.
- Hide unsupported engine categories. SQLite uses `main`; MySQL/MariaDB omit unsupported kinds; Postgres supports its native richer catalog.
- Use opaque catalog object keys and re-resolve them against the live catalog before sampling/describing. Never trust or parse a display-qualified name into SQL identifiers.
- Preserve `nomoreide_db_tables`, `nomoreide_db_sample`, `nomoreide_db_query`, `/tables`, and legacy `TableRef` compatibility.
- Add MCP tools equivalent to:
  - `nomoreide_register_database`
  - `nomoreide_check_database`
  - `nomoreide_db_schemas`
  - `nomoreide_db_objects`
  - `nomoreide_db_object_details`
- Registration checks connectivity by default; allow `check: false` for offline configuration. MCP replacement requires explicit `replace: true`. MCP cannot set write-unlock state and must never expose database writes.
- Redact credential-bearing URL arguments and sensitive errors before MCP tool-call recording/truncation. Never echo raw URLs from registration/check responses.
- Catalog and details load per expanded branch; definitions load on selection and must be size-capped. Branch failures remain local and retryable.
- Node and Rust expose the same camelCase DTO shapes. Tauri must fix its fake `__test__` connection test, hard-coded SQLite result engine, client-built unquoted sampling SQL, missing `projectPath`, non-read-only query paths, and missing write-preview parity.

## Suggested implementation sequence

1. Add canonical catalog types/capabilities and opaque object keys under `src/core/db/`; add credential-redaction regression tests first.
2. Extend `DbDriver`/`DbPeek`; implement SQLite catalog/details, then Postgres and MySQL/MariaDB. Keep legacy adapters.
3. Add HTTP schema/object/detail routes and extend the shared `DatabaseApi` plus HTTP adapter.
4. Add MCP register/check/schema/object/detail tools; fix onboarding/setup references and guarantee safe activity recording.
5. Build the compact lazy multi-connection explorer and object-detail panel; preserve SQL mode and project scope behavior; add English and Chinese strings.
6. Bring Rust config/database commands and the Tauri bridge/adapter to the same contract and safety behavior.
7. Add focused Node, Happy DOM, adapter, and Rust SQLite tests; then run lint, full tests, builds, Cargo formatting/check/tests, and manual web/desktop verification.
